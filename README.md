# 百家号创作者雷达

面向百家号创作者运营人员的本地 Live Beta，用于小批量内部筛选：

1. 通过搜索任务发现抖音内容作者；
2. 将搜索关键词与筛选引进标准分离，由每次业务目标驱动作者判断；
3. 仅使用抖音昵称在天牧大盘作者池查重；
4. 输出内容达标且天牧未匹配的 BD 候选名单。

## 当前完成情况

- 可运行的中文工作台；
- 工作概览、搜索任务、候选池、作者详情和运行日志；
- Mock 模式保留 25 位覆盖主要边界场景的演示创作者；
- 搜索、筛选、天牧查重和最终状态的完整演示；
- 候选池搜索与组合筛选；
- 类目、内容状态、天牧状态与“只看新锐”可组合筛选；
- 筛选条件保存在当前浏览器，刷新后自动恢复；
- 点击创作者昵称可进入详情页；
- 候选池和详情页均提供抖音主页链接；
- 新建、暂停、继续真实任务，并使用原子状态锁防止重复运行；
- 自定义目标类目，或留空由 AI 根据账号内容识别；
- 按账号整体内容归入游戏、动漫、母婴育儿、宠物、生活、三农、历史、科学等业务类目；
- 顶部显示 TikHub API 配置、可用状态和账户余额；
- Live/Mock 运行模式由环境配置真实驱动，空数据库不再混入演示作者；
- 创建任务时预估最坏请求量，并限制每词候选数与每位作者作品采样数；
- TikHub 搜索允许较长响应时间，超时仅退避重试一次；作者主页使用低价单账号接口，7 天内已采集主页直接复用；
- TikHub 异常会记录业务阶段、接口、HTTP 状态和业务错误码，便于区分超时、鉴权、限流和余额问题；
- 运行中任务每 3 秒自动同步真实状态，暂停原因直接展示，不再使用虚拟进度；
- 删除不再需要的搜索任务；
- 单账号失败隔离、任务检查点、失败账号重试、受限账号跳过和人工登录后恢复；
- 独立天牧待查队列：只接收内容推荐作者，人工登录查询并确认后回写结果；
- 人工修改天牧查重结果，登录失效、验证码和无权限时保留待办、不丢任务；
- 独立建联 CRM：D1 持久化入池、阶段、负责人、联系方式、跟进日期、备注及事件记录；
- CRM 当前筛选结果 CSV 导出；
- D1/Drizzle 数据模型；
- 抖音与天牧 Adapter 接口；
- 平台无关 Creator Engine：统一作者证据、基础质量评分与置信度；
- Shadow Mode：保留 LLM 业务匹配结果，同时旁路记录基础质量评分差异；
- 主页或作品接口暂时受限时降级保存搜索证据，不丢失候选作者；
- TikHub 超时、限流、余额不足或上游异常时，可自动切换独立的 Playwright/Crawl4AI 备用采集服务；
- 运行日志页面读取 D1 真实记录，展示数据源切换、采集阶段、警告和失败原因；
- Mock Adapter；
- Playwright Adapter 安全骨架；
- 昵称完全匹配、多同名和特殊符号测试。

## 重要边界

当前版本是 **Live Beta**：

- Live 模式通过 TikHub 接入真实抖音公开数据，不直接登录或抓取抖音网页；
- 已实现 TikHub 搜索、低价单账号主页、近期作品的正式 Adapter；配置密钥和 D1 后由后台任务执行器调用；
- Mock 模式只用于界面演示和离线测试，不会混入 Live 模式的空数据库；
- 当前定位是小批量内部使用，仍需人工抽查结果与持续观察 TikHub 接口稳定性；
- 天牧采用安全的“人工查询 + 系统回写”模式，尚未启用页面自动操作；
- Live 模式仅展示 TikHub 实际返回并成功写入数据库的账号；
- 不会保存抖音或百度账号密码；
- 不会绕过验证码、登录和权限；
- 不会全量抓取天牧作者池；
- 天牧只查询通过内容筛选的作者；
- 天牧查重只使用完整抖音昵称；
- 多个同名或相似昵称只进入人工复核。

## 运行

要求 Node.js 22.13 或更高版本。

```bash
pnpm install
pnpm dev
```

打开 `http://localhost:3000`。

## 候选池筛选与详情

进入“创作者候选池”后，可以同时使用昵称搜索、类目、内容状态、天牧
状态和“只看新锐”。当前筛选条件使用浏览器 `localStorage` 保存；存在
有效筛选时，刷新页面会恢复筛选并返回候选池。

点击创作者昵称或“详情”按钮可进入该作者详情。列表与详情中的“抖音
主页”会在新标签页打开。Mock 模式的主页地址只用于验证交互；Live 模式的
候选账号来自 TikHub 实际返回并由后台任务写入 D1。

如果当前环境的包管理器对依赖脚本使用审批机制，请允许项目
`pnpm-workspace.yaml` 中列出的 `esbuild`、`sharp`、`unrs-resolver` 和
`workerd` 构建脚本。

## 数据结构

核心表位于 `db/schema.ts`：

- `search_tasks`
- `creators`
- `creator_discoveries`
- `works`
- `work_analyses`
- `creator_analyses`
- `creator_shadow_evaluations`
- `tianmu_checks`
- `task_logs`
- `creator_crm_records`
- `creator_crm_events`

未接入真实服务时页面仍可使用 `lib/mock-data.ts` 展示界面。CRM 已改为 D1
服务端持久化读写，并在每次加入或更新时写入事件记录；CSV 导出读取当前
CRM 筛选结果，不再依赖当前浏览器的本地存储。

搜索任务已支持真实 D1/Worker 链路：创建任务、后台执行、检查点、失败隔离、
状态刷新和任务作者结果均有服务端接口。未配置 `TIKHUB_API_KEY` 或
`LLM_API_KEY` 时任务会暂停并写明原因，不会生成伪造的正式结果。

Creator Engine 不替代按业务目标运行的 LLM 判断。它只在旁路记录主页完整度、
活跃度、商业信号和证据置信度，供 `/api/shadow/report` 对照验证；在人工样本
验证稳定前，不会改变正式推荐结论。

### LLM Evaluation V2

正式分析判断的是“账号整体是否符合本次筛选目标”，不是账号的绝对价值，也不以单条搜索命中直接定义作者。证据优先级为：主页定位与近期作品集合 > 搜索命中作品 > 其他弱信号；主页与单条作品冲突时以前者为准。系统会识别偶然命中、内容漂移、搬运切片、强营销和模板化低质内容，并输出匹配理由、风险、建议动作、类目及五项维度分。

评分按 0–39 不建议、40–59 人工判断、60–79 观察补采、80–100 优先联系解释。只有同时取得主页简介和至少三条近期作品，且置信度达标，才允许进入高优先级推荐；证据不足时系统会自动封顶分数，避免把“未采到证据”误判为“没有风险”。

本次候选池交互优化没有修改数据库结构：`creators.profile_url` 已存在，
因此无需新增 Drizzle Migration，也不会覆盖现有数据库。

## 真实页面接入

真实接入应在有权限的本地或百度内网环境逐步完成：

1. 用户手动登录抖音；
2. 用户手动登录天牧；
3. 使用持久化浏览器 Profile 复用登录态；
4. 在 `lib/adapters/selectors.ts` 填写人工确认过的稳定选择器；
5. 单独验证登录态检测；
6. 单独验证抖音搜索、作者主页和作品解析；
7. 单独验证天牧昵称搜索和无结果状态；
8. 出现验证码、风险提示、无权限或登录失效时立即暂停；
9. 通过小批量人工抽查后再逐步提高任务量。

Adapter 文件：

- `lib/adapters/types.ts`：接口与返回结构；
- `lib/adapters/mock.ts`：完整 Mock 实现；
- `lib/adapters/playwright.ts`：真实页面安全骨架；
- `lib/adapters/selectors.ts`：集中管理页面选择器。
- `lib/adapters/fallback-service.ts`：主应用调用备用采集服务的安全接口；
- `fallback_crawler/`：独立 Python/Playwright/Crawl4AI 服务模板。

备用服务不是验证码或权限绕过工具。未登录、出现验证码、无权限或选择器未配置时，任务会暂停并写入真实日志，等待人工处理。

## 天牧昵称规则

- 默认使用原始完整昵称；
- 自动处理仅限去除首尾空格；
- 不删除括号、点号、表情、数字或特殊字符；
- 唯一完全同名结果：`MATCHED`；
- 无结果：`NOT_MATCHED`；
- 多个完全同名结果：`REVIEW_REQUIRED`；
- 相似昵称：`REVIEW_REQUIRED`；
- 不使用模糊结果自动判定作者已入驻。
